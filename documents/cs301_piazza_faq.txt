Q: Give a True/False example from Exam 1 style: If A is recognized by an NFA and B is generated by a regular expression, is A ∩ B̄ necessarily regular?
A: TRUE. If A is recognized by an NFA, then A is regular (NFAs recognize exactly regular languages). If B is generated by a regular expression, then B is regular. Regular languages are closed under complement and intersection. Therefore A ∩ B̄ is regular.

Key closure facts to memorize: Regular languages are closed under union, intersection, complement, concatenation, Kleene star, and reverse.

Q: How do I check if a string is in A − B?
A: A − B = A ∩ B̄. A string w ∈ A − B if and only if w ∈ A AND w ∉ B.

Example from Exam 1: Is 000 ∈ A − B where A = {w | w contains at least one 0} and B = {w | w contains an even number of 1's}?
- 000 ∈ A (it contains 0's) ✓
- 000 ∈ B (it contains zero 1's, and zero is even) ✓
- Therefore 000 ∉ A − B (not in A but not NOT in B). Answer: No.

Q: How do I construct an NFA for Kleene star of a language?
A: The correct construction (from Exam 1 short answer):
Given NFA N with start state q0 and accept states F:
1. Add new start state s that is also an accept state
2. Add ε-transition from s to q0
3. Add ε-transitions from every state in F back to s

This correctly handles ε (via the new accepting start state) and repetition (via the back-ε-transitions). See HW1 doc for why the naive construction fails.

Q: How do I convert an NFA to a DFA using subset construction?
A: Label each DFA state as a SET of NFA states. Algorithm:
1. Start state = ε-closure of NFA start state
2. For each DFA state S and each symbol a: compute δ(S, a) = ε-closure(⋃_{q ∈ S} δ_NFA(q, a))
3. A DFA state is accepting if it contains any NFA accepting state
4. Only track REACHABLE states (ignore unreachable ones)
5. Include the dead state ∅ if needed (non-accepting trap state)

Example from Exam 1: NFA with states {1, 2, 3} and transitions including ε.
Start DFA state = ε-closure({1}) = {1} (accepting since 1 is accept state in NFA).
On 'a': from {1}, go to {2}. From {2}, ε-closure gives {2}. So DFA has state {2}.
Continue until all reachable DFA states are enumerated.

Q: How do I convert an NFA to a regular expression using the GNFA method?
A: Steps:
1. Convert NFA to GNFA: add new start state s (ε to old start) and new accept state a (ε from old accepts). Old accepts become non-accepting.
2. Repeatedly remove ONE interior state q at a time:
   - For each pair of remaining states (q_i, q_j), update the label of the direct transition from q_i to q_j
   - New label = (old q_i → q_j) | (q_i → q)(q loop)*(q → q_j)
3. When only s and a remain, the label on s → a is the regular expression.

From Exam 1 (NFA with q0 and q1):
Two possible orders of removal give two equivalent expressions:
- Remove q0 first: result is 1*0(1 | 01*0)*
- Remove q1 first: result is (1 | 01*0)*01*
Both are correct (different but equivalent regular expressions).

Q: How do I tell if a grammar is regular (right-linear or left-linear)?
A: A grammar is regular if it is right-linear OR left-linear:
- Right-linear: every rule is of the form A → wB or A → w (terminal string, optional variable at the END)
- Left-linear: every rule is of the form A → Bw or A → w (variable at the START or just terminals)

Example from Exam 2: S → aS | abT, T → ab | ε
Every rule has a variable only at the right end of the right side (or is all terminals). This is right-linear → regular grammar. Answer: Yes.

Q: What rules are NOT allowed in CNF?
A: CNF allows ONLY: A → BC (two variables) and A → a (one terminal) and S0 → ε.

NOT allowed (from Exam 2):
- S → A (unit rule — exactly one variable)
- A → ABC (three symbols — too long)
- A → AS (two variables but also a unit issue? No, AS is fine — it's two variables. But wait: AS has two variables ✓. Actually A → AS is valid CNF since it's two variables. Check: A → ABC has three variables → NOT CNF.)
- B → aC (mixed terminal + variable → NOT CNF)
- C → ab (two terminals → NOT CNF)
- C → ε (ε-rule for non-start variable → NOT CNF)

Q: How do I convert a grammar to CNF? Show an example.
A: Example from Exam 2: S → 0S1 | T | ε, T → 00 | 11

START: Add S0 → S.
  S0 → S; S → 0S1 | T | ε; T → 00 | 11

BIN: Fix S → 0S1 (3 symbols):
  S → 0U; U → S1 (new variable U)

DEL: Fix S → ε. S is nullable. Update rules:
  S0 → S | ε; S → 0U | T; U → S1 | 1

UNIT: Fix S0 → S and S → T:
  S0 → 0U | 00 | 11 | ε; S → 0U | 00 | 11; U → S1 | 1; T → 00 | 11

TERM: Fix rules with mixed terminals/variables. Add X → 0, Y → 1:
  S0 → XU | XX | YY | ε; S → XU | XX | YY; U → SY | 1; T → XX | YY; X → 0; Y → 1

Q: How do I interpret a Turing Machine's behavior on input?
A: Trace the computation state by state. Key terms:
- Initial configuration: q0 w (start state, full input)
- Final configuration: ... q_accept ... or ... q_reject ...
- Accept: head enters accept state
- Reject: head enters reject state OR head stays in non-halting computation (loop)

Example from Exam 2: TM with states q0, q1, q2, q3, q4 (accept).
String "ab" accepted → final config: xq4y (meaning the tape contains x, then y, and the head is at state q4 between them).
String "aa" rejected → initial config: q0aa.
